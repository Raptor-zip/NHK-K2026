# プロモ映像（Blender / Cycles）

`cad/urdf/tr.urdf` と材質別 STL をそのまま使って、TR の宣材写真と PV を作る。
CAD の形と関節はビューアや検査群と同じものを見ているので、機体を直せば映像も
作り直すだけで追従する。

```
screen.py      表示器に映す画（1280×800）→ tex/screen.png
scene.py       URDF → Blender シーン（材質・照明・ホリゾント背景）→ tr_promo.blend
shots.py       .blend を開いてカメラを置き、静止画／連番を撮る
render_all.sh  全ショットを撮って 1 本の mp4 にまとめる
```

## 用意するもの

- Blender 4.5 LTS（`~/opt/blender-4.5.12-linux-x64/blender` を既定で見る。
  `BLENDER=` で差し替えられる）
- 映り込み用の HDRI（Poly Haven / CC0）

```bash
mkdir -p cad/promo/hdri && cd cad/promo/hdri
curl -O https://dl.polyhaven.org/file/ph-assets/HDRIs/exr/2k/brown_photostudio_02_2k.exr
mv brown_photostudio_02_2k.exr brown_photostudio_02.exr
```

HDRI はカメラには写らない。暗いホリゾントの内側で、金属に映り込む景色として
だけ効く。無くても動く（真っ暗な環境として扱われ、映り込みが減る）。

## 手順

```bash
cd cad/promo
B=~/opt/blender-4.5.12-linux-x64/blender

# 1. シーンを組む（STL 60 個の読み込みで 2 分ほど。46 万三角形）
$B -b --factory-startup -noaudio -P scene.py -- --out tr_promo.blend

# 2. 絵づくりを直したら、機体は読み直さず環境と材質だけ作り直す（30 秒）
$B -b --factory-startup -noaudio -P scene.py -- --out tr_promo.blend --relight

# 3. 構図あたり
$B -b tr_promo.blend -P shots.py -- preview              # 6 アングル
$B -b tr_promo.blend -P shots.py -- contact              # 各ショットの頭・中・尻

# 4. 1 枚だけ本気で
$B -b tr_promo.blend -P shots.py -- still --az 46 --el 8 --lens 55 \
    --samples 512 --res 3840x2160 --out out/hero.png

# 5. 動画（1920x1080 / 30fps、GPU で 3 時間ほど）
./render_all.sh
SAMPLES=24 RES=960x540 ./render_all.sh    # 下見ならこれで 20 分
```

## ショット構成（30fps・合計 28 秒）

| ショット | 尺 | 中身 |
|---|---|---|
| `a_wake` | 3.7s | 暗がりから灯りが順に入り、寄っていく |
| `b_orbit` | 6.7s | 180° 回り込み。途中で砲塔が起きる |
| `c_turret` | 4.7s | 砲塔のヨー・ピッチ。ローラーは 6 rev/s で流れる |
| `d_grabber` | 4.7s | 回収機構。スライド伸長・フォーク傾け・押さえ降下 |
| `e_drive` | 3.7s | 足元を舐める。車輪が回る |
| `f_finale` | 5.0s | 引きながら上がって、構えで止まる |

ショットは `shots.py` の `SHOTS` に方位角・仰角・距離・画角の始点と終点で
書いてある。`dist_mode="fit"` なら「機体が画面に収まる距離」への倍率、
`"abs"` なら実距離[m]。関節は `pose_from`／`pose_to` を補間し、回り続ける
ものは `spin`（rev/s）で回す。

## 静止画の構成（`stills.sh`・2560×1440 / 512 サンプル・1 枚 70 秒ほど）

| ショット | 姿勢 | 中身 |
|---|---|---|
| `hero` | match | 前 3/4 の定番カット |
| `hero_low` | match | 低い位置から煽る。広角で迫力を出す |
| `rear34` | load | 後ろ 3/4。表示器とグラバーが見える |
| `turret` | match | 砲塔まわりの寄り |
| `grabber` | load | フォーク伸長・押さえ降下の寄り |
| `topdown` | match | 俯瞰。骨格の通り方を見る |
| `display` | match | 8 インチ表示器の寄り。画が点いているかを見る |
| `lidar_front` | match | 前 LiDAR の水平出し座の寄り（検査用） |

⚠ **ここに書いた 8 枚が `out/stills/` の全部**。以前は `display` と
`lidar_front` を手打ちで撮っていて `stills.sh` に無く、CAD を出し直すたびに
この 2 枚だけ古いまま残っていた。**新しい構図は必ず `stills.sh` に足す。**

## 絵づくりの勘所

ここでハマったところを残す。

- **GPU の割り当ては .blend に保存されない。** `scene.cycles.device='GPU'` は
  保存されるが、どのデバイスを使うかはユーザー設定側にある。`shots.py` は
  開くたびに `enable_gpu()` で OptiX を指定し直す。これを忘れると黙って CPU に
  落ちて 4 倍遅くなる（20s→80s/frame）。
- **HDRI をそのまま背景にすると台無しになる。** Light Path の `Is Camera Ray`
  で分岐し、映り込みには HDRI、カメラには暗いグラデーションを見せる。
  Mix Shader は Fac=0 で入力 1、Fac=1 で入力 2 なので、繋ぎ間違えると
  背景に窓や木が写る。
- **床は平面ではなくホリゾント（回転体）。** 平面＋背景板だと必ず境目の線が
  出る。床から壁へ 1 枚でつなぐと、背景が「どこまでも続く暗がり」になる。
  壁に上がるほど艶消しにして、映り込むのは床だけにしてある。
- **材質の色は CAD のものを使わない。** `materials.json` の rgba は材質を
  見分けるための色でしかない。`scene.py` の `MATERIALS` で金属度・粗さ・
  クリアコートを与え直し、粗さはノイズでわずかに散らす（一様な粗さは
  CG くさく見える）。金属の明度は実物より落としてある（明るいままだと
  暗い背景の中で白い塊になる）。
- **表示器は「点いている」ところまで作る。** 8 インチ表示器を 195×122×14 の箱
  ひとつで描くと材質が 1 つしか付かず、白い板が立っているだけになる。CAD 側で
  ベゼルと有効表示領域（172.3×107.7 / 材質 `SCREEN`）を分けてあるので、
  `scene.py` はそこへ `tex/screen.png` を **Emission** で貼る。画が無ければ
  `screen.py` を自動で回す（Blender の Python には Pillow が無いので、
  実際に描くのは `cad/.venv` 側）。
  - **貼るのは Generated 座標**。メッシュは STL 由来で UV を持っていない。
    板は X 薄・Y 幅・Z 高で、見るのは -X 側なので `u = 1 - y` / `v = z`。
    `u = y` にすると**鏡文字**になる（板が薄いので形では気づけない）。
  - 表示内容を CAD の形として入れない。画面に出ているのは画素で、部品ではない。
    ロゴを 0.3mm の板として組立に足すと、STEP と部品表に実在しない部品が増える。
- **コースティクスと霧は切ってある。** 透明バケツのコースティクスは絵に
  効かないわりに 1.5 倍重く、ノイズも残る。霧（`--haze`）は光条が出て
  雰囲気は上がるが、薄くしても床が白く曇るので既定は 0。
- **回転のキーフレームは全部リニアにする。** ベジエ補間だと連続回転が
  行き過ぎて巻き戻る。
- **モーションブラーは回転が写るショットだけ。** サンプルが時間方向にも
  散るので、静かなショットに入れるとノイズが増えるだけで得がない。

## 関節の作り

URDF の 1 関節を Empty 4 段で表す。

```
親リンク → J_<関節>（origin の xyz/rpy）
        → A_<関節>（軸を +Z に合わせる回転 R）
        → D_<関節>（★ここを動かす。Z 回転 or Z 移動）
        → L_<子リンク>（R⁻¹ で軸合わせを戻す）→ メッシュ
```

こうしておくと軸が `(0,-1,0)` や `(-1,0,0)` でも、動かすのは D の 1 自由度
だけで済む。`D_*` には `tr_joint` / `tr_type` のカスタムプロパティが載って
いて、`shots.py` は名前で引く。

## 画質の勘所（ここが一番効く）

- **「解像していない」と感じたら、まず絞りを疑う。** サンプル・解像度・デノイザより先。
  プロダクト写真は f/8〜16 で製品全体にピントを合わせるのが基本で、ボケは背景を
  落とす用途に限る。f/2.8 で撮ると被写界深度が数センチしかなく、2560x1440 で
  出しても画面のほぼ全域がピント外になる（サンプルを 5 倍にしても改善しない）。
- **絞ってもレンダリング時間はほとんど変わらない**（実測 26.7→31.1 秒）。迷ったら絞る。
- **`adaptive_threshold` を既定 0.01 のままにしない。** 「ノイズが 1% を切ったら
  打ち切る」設定で低サンプルのまま止まり、そこへデノイザが強く効いてディテールが
  溶ける。静止画 0.004 / 動画 0.007 くらい。
- **手続きノイズの scale は画素に落ちる大きさで決める。** 部材幅が画面上 50〜200 px
  なら scale 100〜300 が目安。scale 2000 のノイズは 1 px より細かく、
  ディテールではなくジリつきになる。
- 設定を変えたら実測してから本番を回す。

```bash
blender -b tr_promo.blend -P quality_test.py -- --res 1280x720
```

## やってはいけないこと

- **実行中のシェルスクリプト（`stills.sh` 等）を書き換えない。** bash は
  スクリプトを逐次読み込むので、実行中に行数が変わると読み位置がずれて壊れる。
  実際にこれで 6 枚中 3 枚が焼かれずに終了した。
- **待ちループを `pgrep -f 'stills.sh'` で書かない。** バックグラウンドジョブの
  コマンドラインに文字列が含まれ、自分自身にマッチして無限ループする。
  `pgrep -f blender` のように実体を見る。
- **光源の `visible_glossy` を切らない。** 床に映る虚像は消えるが、金属の艶は
  光源の映り込みそのものなので機体が真っ黒に沈む。
